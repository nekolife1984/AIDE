# コミットメッセージ

## 書式

```text
<種別>: <変更内容> (#<Issue番号>)
```

- 日本語で、変更内容が具体的に伝わる短い件名にする。
- `(#Issue番号)`は関連Issueがある場合に付ける。関連Issueがなければ省略する。
- 1コミットには、1つの論理的な変更をまとめる。
- 件名だけで意図が伝わらない場合は、空行の後に理由・背景・注意点を本文へ記載する。
- Issueの完了はコミットではなく、PRとIssue管理ルールに従う。

## 種別

| 種別 | 用途 |
|---|---|
| `機能` | 機能の追加・変更 |
| `修正` | 不具合の修正 |
| `文書` | 文書のみの変更 |
| `テスト` | テストの追加・変更 |
| `リファクタ` | 振る舞いを変えない構造整理 |
| `保守` | 依存関係・開発ツールなどの保守 |
| `CI` | CI/CD設定の変更 |
| `性能` | パフォーマンスの改善 |
| `取消` | 既存コミットの取り消し |

変更の目的に最も合う種別を1つ選ぶ。

## 例

```text
機能: 設定ファイルの再読み込みを追加 (#12)
修正: 空の入力で発生する例外を処理 (#18)
文書: ブランチ運用の手順を追記 (#21)
テスト: 設定読み込みの境界条件を追加 (#24)
リファクタ: 設定解析の責務を分離 (#25)
保守: 開発依存を更新 (#26)
CI: テスト対象のPythonバージョンを追加 (#27)
性能: 検索結果をキャッシュして応答を高速化 (#28)
取消: 「機能: 設定の再読み込みを追加」を取り消し (#29)
```

## 本文の例

```text
修正: 設定ファイルがない場合の起動エラーを解消 (#30)

初回起動時に設定ファイルが未作成でも、既定値で起動できるようにする。
```
